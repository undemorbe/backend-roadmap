# Лабораторная 9. Наблюдаемость для маркетплейса

Микросервисы, примерно 1,5 нед. Открывается после станции «Наблюдаемость: логи, метрики, трейсы».

Сделать систему из лабораторной 6 прозрачной: видеть каждый запрос насквозь и узнавать о проблеме раньше пользователя.

## Стек

- Prometheus
- Grafana
- OpenTelemetry
- Jaeger или Tempo
- Loki

## Требования

- RED-метрики на всех HTTP и gRPC ручках, метрики консьюмеров Kafka (лаг).
- Сквозной трейс от gateway через Kafka до notification.
- trace_id в каждой строке лога, логи собраны в Loki и связаны с трейсами.
- Дашборд на каждый сервис и общий дашборд саги.
- SLO на оформление заказа и алерты на его нарушение.

## Этапы

1. Метрики и Prometheus.
2. Трейсинг HTTP и gRPC, затем распространение контекста через Kafka.
3. Логи и связь с трейсами.
4. Дашборды, SLO, алерты.


## Критерии приёмки

- [ ] Внеси задержку 2 секунды в payment: алерт срабатывает, трейс показывает виновника.
- [ ] Один трейс содержит спаны всех пяти сервисов.

## Со звёздочкой

- Хаос-тест: случайные отказы через toxiproxy.
- Непрерывное профилирование в Pyroscope.
