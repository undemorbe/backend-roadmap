# Лабораторная 4. Деплой на VPS: Nginx, HTTPS и CI/CD

Инфраструктура, примерно 1 нед. Открывается после станции «Архитектура: от монолита к микросервисам».

Выкатить сервис бронирования из лабораторной 3 в интернет так, как это делают в небольших компаниях: свой сервер, Nginx, HTTPS, автоматический деплой и бэкапы.

## Стек

- VPS или локальная ВМ (multipass)
- Docker Compose
- Nginx
- Let's Encrypt
- GitHub Actions
- GHCR

## Требования

- Сервер: вход только по SSH-ключу, отдельный пользователь без root, firewall (ufw) открывает только 22, 80 и 443.
- Compose для продакшена: сервис, PostgreSQL на volume, Nginx. База не публикует порт наружу.
- Nginx: reverse proxy, HTTPS через Let's Encrypt с автопродлением, редирект с HTTP, HSTS, `limit_req` на вход.
- GitHub Actions: на push в main собирается образ, публикуется в GHCR с тегом коммита и выкатывается на сервер по SSH.
- Миграции применяются при деплое до старта новой версии.
- Ежедневный бэкап базы через `pg_dump` по расписанию, хранение 7 дней.
- Откат на предыдущую версию одной командой по тегу образа.

## Этапы

1. Подготовка сервера и Compose без HTTPS.
2. Nginx и HTTPS.
3. Пайплайн деплоя.
4. Бэкапы и проверка восстановления.
5. Runbook в README: как выкатить, откатить и восстановить базу.

## Структура проекта

```
deploy/
  docker-compose.prod.yml
  nginx/conf.d/app.conf
  scripts/backup.sh
  .github/workflows/deploy.yml
  RUNBOOK.md
```

## Критерии приёмки

- [ ] Push в main оказывается на сервере меньше чем за 5 минут без ручных действий.
- [ ] Перезагрузка сервера: всё поднимается само.
- [ ] Бэкап реально восстанавливается в чистую базу (проверено, а не предположено).
- [ ] SSL Labs ставит оценку A или выше.
