# Лабораторная 5. Кэш и лимиты для сервиса бронирования

Монолит, примерно 1 нед. Открывается после станции «Redis и кэширование».

Ускорить и защитить сервис из лабораторной 3 и доказать результат цифрами.

## Стек

- Redis
- go-redis
- singleflight
- k6

## Требования

- Cache-aside для списка площадок и свободных слотов, инвалидация при бронировании.
- Rate limiter на sliding window: отдельные лимиты на вход и на бронирование, ответ 429 с Retry-After.
- Защита от cache stampede.
- Сервис продолжает работать при недоступном Redis (деградация, а не падение).

## Этапы

1. Нагрузочный сценарий k6 и замер без кэша.
2. Кэш и инвалидация, повторный замер.
3. Rate limiter и тесты на него.
4. Отчёт в README: p50, p95, p99 и RPS до и после.


## Критерии приёмки

- [ ] p95 чтения слотов снизился минимум в 3 раза.
- [ ] Остановка Redis не роняет сервис, это покрыто интеграционным тестом.
- [ ] Кэш никогда не показывает занятый слот свободным дольше заданного TTL.
