# Лабораторная 3. Монолит: сервис бронирования

Монолит, примерно 3 нед. Открывается после станции «Архитектура: от монолита к микросервисам».

Главная лабораторная по монолиту: собрать всё из модулей HTTP, SQL, Docker, тестов и архитектуры в один сервис продакшен-качества.

## Стек

- Go
- chi или net/http
- PostgreSQL
- pgx и sqlc
- goose
- JWT
- testcontainers-go
- Docker Compose
- GitHub Actions

## Требования

- Сущности: пользователи, площадки (переговорки, столики, корты), слоты, бронирования.
- Регистрация и вход, роли user и admin. Админ создаёт площадки, пользователь бронирует.
- Двойное бронирование одного слота невозможно даже при параллельных запросах. Используй exclusion constraint на `tstzrange` или блокировки.
- Отмена брони, история броней пользователя с курсорной пагинацией.
- Пользователь видит и отменяет только свои брони.
- Ошибки в формате Problem Details, валидация входных данных.
- OpenAPI-спецификация, миграции, конфиг через окружение, graceful shutdown, healthz и readyz.

## Этапы

1. Схема базы и миграции, ERD в README.
2. Domain и usecase с unit-тестами на fake-репозиториях.
3. Репозитории на pgx и sqlc с интеграционными тестами через testcontainers.
4. HTTP-слой, middleware (логи, request id, recovery, auth).
5. Dockerfile, docker-compose, Makefile, CI.

## Структура проекта

```
booking/
  cmd/api/main.go
  internal/domain/          # сущности и ошибки домена
  internal/usecase/         # сценарии и интерфейсы репозиториев
  internal/adapter/postgres # реализации репозиториев
  internal/adapter/http     # хендлеры, middleware, dto
  internal/config/
  migrations/
  api/openapi.yaml
  docker-compose.yml
  Makefile
```

## Критерии приёмки

- [ ] Тест: 100 горутин одновременно бронируют один слот — успешна ровно одна.
- [ ] `make up` поднимает всё с нуля, `make test` проходит.
- [ ] Usecase-слой не импортирует ни pgx, ни net/http.
- [ ] Образ меньше 25 МБ, CI зелёный на каждый pull request.
